# 권리자(라이선스를 가진 쪽) 흐름 — 초안 (2026-10-24)

배경은 [license.md](license.md), 방향은 [direction.md](direction.md). 이 문서는 "권리자가 오리에 들어와서 라이선스를 걸고, 값을 정하고, 돈을 받고, 관리하는" 과정을 처음부터 끝까지 잡은 설계 초안이에요. 아직 만든 기능은 단체 쪽 신청(①)까지예요.

비유: 오리는 **공연권 부동산**이에요. 집주인(권리자)이 집(작품)을 내놓고, 세입자(단체)가 빌리러 와요. 오리는 매물 사진을 걸어 주고, 임대 조건을 표준 계약서로 정리하고, 보증금을 맡아 두었다가 넘겨주고, 중개 수수료를 받아요.

## 1. 들어오기 (권리자 등록)

**처음 몇 곳은 오리가 먼저 찾아간다.** 권리자는 "아마추어 시장"이 있는지 모르니까, 수요 보드의 숫자(원하는 단체 수·정식 신청 수, 이름 없이)와 권리자용 CSV를 들고 간다. 첫 딜이 성사되면 그 권리자를 오리가 대신 등록해 준다 (컨시어지).

그 뒤엔 스스로 들어올 수 있게:
- 사이트 아래·라이선스 화면에 **"권리자이신가요?"** → 권리자 소개 페이지 (`#for-rights-holders`): 이 작품을 원하는 사람 수, 오리가 대신 해 주는 일, 수수료.
- **권리자 등록 신청**: 구글 로그인 → 회사·개인 이름, 사업자번호(있으면), 담당자 연락처, **권리 증빙**(원작 계약서의 권리 범위 부분, 번역 허락서 등).
- 오리 운영자가 어드민 "권리자 승인"에서 확인(서류 + 전화) → 승인되면 그 사람에게 **권리자 화면**이 열린다.
- 한 회사에 여러 담당자: 대표가 다른 사람을 초대 (단체 관리자와 같은 방식).

## 2. 작품 걸기

권리자 화면 → **내 작품 → 작품 걸기**
- 오리 아카이브에 이미 있는 작품이면 골라서 잇고, 없으면 새로 만든다.
- **권리 두 겹**을 따로 적는다 (license.md): 원작의 문 / 번역의 문. 한쪽만 가진 권리자는 그쪽만 건다. 두 겹이 다 걸려야 단체가 바로 신청할 수 있고, 한쪽만이면 "협의 가능"으로 보인다.
- 권리 범위: 지역(한국), 언어(한국어 대본), **계약 만료일**, 아마추어 허용 여부, 각색 허용 범위(대사 수정·성별 바꾸기·장면 삭제).
- 막는 조건: 예) "본공연 기간 중 서울 공연 불가", "최대 객석 300석", "유튜브 전막 업로드 금지".
- 함께 주는 자료: 대본, 악보, MR, 연출 노트, 포스터 원본 (파일은 오리 저장소에 한 번만 올린다).
- 저장하면 작품 페이지와 라이선스 목록에 "라이선스 제공"·권리자 이름이 걸린다. 지금 어드민에서 운영자가 켜는 "권리 정보 공개"를 권리자가 직접 하는 셈이다.

## 3. 값 정하기 (가격표)

MTI처럼 **공연마다 견적**을 낸다. 권리자는 셋 중 하나를 고른다 (오리가 틀을 준다).

1. **회차당 정액**: 회차당 ○원. 예) 회차당 30만원 × 4회 = 120만원. 아마추어에 가장 쉽다 → **기본값**
2. **구간표**: 객석 수 × 티켓 가격 구간에 따라 회차당 금액. 예) 100석 이하·티켓 2만원 이하 → 회차당 20만원
3. **매출 비율**: 티켓 매출의 ○% + 최소 보장액. 공연 뒤 매출 보고가 필요하다 → 나중 단계

추가 항목:
- 자료 대여료 (대본 권당, 악보·MR 세트), 보증금(자료 반납·위반 대비, 선택)
- **무료 공연 할인**: 티켓 무료·출연료 없음이면 할인 또는 무료 (저작권법 29조 경계지만 번역 대본은 허락이 필요하니까)
- 오리가 **"비슷한 작품 시세"**를 보여준다 (모인 계약이 3건 이상일 때만, 비용 감처럼).

**오리 수수료**: direction.md대로 **건당 정액**(예: 계약 1건당 ○만원)을 기본으로 한다. 단체가 내는 금액에 얹을지, 권리자 몫에서 뗄지는 태준님이 정할 일이다 (아래 "정할 것").

## 4. 신청·견적

- 단체는 지금 있는 라이선스 화면(`#license-<id>`)의 ① 공연 정보로 신청한다: 누구로·시기·회차·티켓·출연료·한마디. 여기에 **객석 수·티켓 가격·공연 장소**를 더 받는다 (가격표 계산용).
- 가격표가 있으면 **견적이 바로 계산**되어 단체에게 보인다 ("예상 금액 120만원 + 오리 수수료").
- 권리자 화면 **"들어온 신청"**: 승인 / 조건 달아 승인(금액·조건 수정) / 거절(사유). **7일 안에 답이 없으면** 오리가 권리자에게 알리고, 14일이면 단체에게 "답이 늦어지고 있어요"라고 알린다.
- 신청 상태는 한 줄로 흐른다: `신청 → 견적 → 승인 → 계약 → 결제 → 자료 → 공연 → (보고) → 정산 완료`. 단체 화면의 5단계 표시가 이 상태를 그대로 보여준다.

## 5. 계약

- 오리 **표준 라이선스 계약서**: 작품·권리 범위·공연 조건·금액·크레딧 표기·자료 사용 범위·위반 시 처리 칸이 자동으로 채워진다.
- 양쪽이 **전자 서명**한다. 처음엔 PDF에 서명해 올리고, 나중에 전자계약 서비스(모두싸인 등)와 잇는다.
- 계약서는 권리자·단체·오리가 모두 언제든 다시 내려받을 수 있다.

## 6. 결제

- 단체는 **오리에 결제**한다: 카드 / 계좌이체 / (단체가 사업자면) 세금계산서.
  - 처음: 계좌이체 + 운영자가 입금 확인 (어드민 "입금 확인" 버튼)
  - 나중: PG(토스페이먼츠 등) 연동
- 오리는 돈을 **맡아 둔다** (에스크로). 자료가 열리고 공연이 확정되면 권리자 몫이 된다.
- 공연이 취소되면: 자료를 열기 전이면 전액 환불, 연 뒤면 계약서의 환불 조항대로.

## 7. 자료 받기

- 결제가 끝나면 단체 프로젝트에 **"자료함" 상자**가 생긴다 (프로젝트 보드의 "작품·라이선스" 상자 안).
- 대본 PDF에는 **단체 이름과 계약 번호를 워터마크**로 박는다. 열람·다운로드는 **공연 종료 + 30일**까지만 하고, 누가 언제 받았는지 기록을 남긴다.
- 대본·악보·음원은 오리 아카이브 어디에도 공개되지 않는다 (direction.md: 허락 범위 안에서만).

## 8. 공연·보고

- 오리가 **크레딧 문구**를 준다: "이 공연은 ○○의 허락을 받아 올립니다." 단체는 포스터·프로그램북에 넣는다 (홍보 상자에 체크리스트).
- 매출형 계약이면 공연 뒤 7일 안에 **매출·관객 수를 보고**한다 (티켓 판매 화면 캡처 첨부).
- 프로젝트가 "공연 완료"가 되면 공연 기록이 아카이브에 **"권리 확인"**(`record_status`)으로 올라간다. 처음으로 신뢰도 맨 위 단계가 자동으로 채워진다.

## 9. 정산

- **매달 한 번**, 그달 정산 가능한 건(자료 열림 + 공연 확정)을 묶어 오리 수수료를 떼고 권리자 계좌로 보낸다.
- 권리자 화면 **"계약·정산"**: 건별 금액, 수수료, 지급일, 정산서 PDF.
- 세금계산서·원천징수는 누가 누구에게 발행하는지 구조에 따라 달라진다 → 세무 확인이 필요하다 (아래 "정할 것").

## 10. 후속 관리

권리자 화면이 계속 쓸모 있게:
- **내 작품의 공연**: 오리로 허락받아 올라간 공연 목록·지도·누적 회차·관객 (권리 확인된 것만. 미확보 공연은 개별로 보여주지 않는다, direction.md).
- **기다리는 수요**: 아직 안 연 작품의 "원해요" 수·정식 신청 수 → "이 작품도 열어 볼까요?"
- **계약 만료 알림**: 만료 90일 전에 권리자·오리에게. 연장하거나 내린다 (진행 중인 계약은 끝까지 유효).
- **조건 바꾸기**: 가격표·막는 조건은 언제든 바꿀 수 있고, 이미 맺은 계약에는 영향이 없다.
- **문제가 생기면**: 계약 위반(크레딧 누락, 허락 범위 밖 각색 등)은 권리자가 "문제 알리기" → 오리가 중재한다. 오리는 무단 공연을 찾아내 고발하는 도구가 아니다 (license.md "지켜야 할 선").

## DB (만들 것, 이름은 가안)

- `rights_holders` 권리자(회사·개인), `rights_holder_members` 담당자, 증빙 파일, `verified_at`
- `work_licenses` 작품 × 권리자 × 겹(원작/번역): 범위·만료일·아마추어 허용·막는 조건·가격표(jsonb)·자료 목록
- `license_applications` 지금의 `license_demands`를 키워서 상태(`신청…정산 완료`)·견적·승인 조건을 담는다
- `license_contracts` 계약서 파일·서명 시각, `license_payments` 결제·환불, `license_payouts` 월 정산
- RLS: 권리자는 자기 작품·자기 신청만, 단체는 자기 신청만, 금액·계약은 당사자와 운영자만

## 단계별로 만드는 순서

0. **지금 (손으로)**: 첫 딜은 오리가 다 대신한다. 이메일로 가격 합의 → 계약서 PDF → 계좌이체 → 대본은 메일로. 사이트에는 "협의 가능" 표시와 신청만 있다 (지금 상태).
1. **권리자 화면 1차**: 권리자 등록·승인, 작품 걸기, 들어온 신청 보기·답하기, 회차당 정액 가격표 → 자동 견적. 결제는 계좌이체 + 운영자 확인.
2. **계약·자료**: 표준 계약서 자동 작성 + 서명 파일, 자료함(워터마크·기간 제한).
3. **결제·정산 자동화**: PG 연동, 월 정산서, 매출형 가격표·매출 보고, 만료 알림.

## 태준님이 정할 것 (법률·세무 상담 때 같이)

1. **돈의 길**: (가) 단체 → 오리 → 권리자 (오리가 중개하며 맡아 둠) / (나) 단체 → 권리자에게 직접, 오리는 수수료만 청구. 가는 경험이 좋지만 통신판매중개업·에스크로·세금 처리가 무겁고, 나는 가볍지만 오리가 흐름을 놓친다. → **추천: 처음엔 (나)로 시작해 수수료만 받고, 거래가 쌓이면 (가)로**
2. **수수료**: 건당 정액(direction.md)인지 금액의 %인지, 누가 내는지(단체에 얹기 / 권리자 몫에서 떼기)
3. **표준 계약서**: 저작권 전문 변호사 검토 1회 (기존 법률 상담과 묶기 — public-scope.md 7번 질문 목록에 추가)
4. **사업자 등록 업종**: 통신판매중개업 신고가 필요한지
5. **자료 보관**: 대본 파일을 오리 저장소에 두는 것의 책임 범위 (유출 시)
